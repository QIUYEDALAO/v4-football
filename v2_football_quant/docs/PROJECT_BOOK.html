3. V2 引擎核心: att_def_spread 分档模型

核心理念: 将每场比赛的攻防实力差 (att_def_spread) 分为 10 档，每档拥有独立的 HT 1X2 概率分布，基于 2,322 场历史比赛统计。

3.1 工作流 (每日 08:00 BJT)

  1. 拉取赛程: API-Football /fixtures → 未来 24h 白名单比赛
  2. 计算 att_def_spread: 基于近 5 场主客队得失球率差值
  3. 分档: 10 档 (档5 ≈ 实力均衡)
  4. 查表: fair_odds_matrix.json → H/D/A 公平赔率
  5. 比价: Pinnacle 实时赔率 vs 公平赔率 → Edge (%)
  6. 过滤: Edge > 5% 信号 → 推荐清单
  7. 保存: predictions_YYYYMMDD.json → 等待次日结算

3.2 分档统计 (10档 · 2322场历史)

档位att_def_spread典型场景H%D%A%
1< -30客队碾压 (如PSG客战垫底队)10%18%72%
3-20 ~ -10客队占优20%30%50%
5-10 ~ +10实力均衡 (如拜仁vs巴黎)38%32%30%
7+10 ~ +20主队占优48%28%24%

3.3 已发现的信号特征

三场推荐全部为 档5 (均衡) → 推半场平局(D)。这是档5模型概率 32% 的自然倾向——均衡比赛中平局是最容易被低估的结果。

7.3 深度剖析: 为什么 "全红但全负 CLV"

7.3.1 现象

三场推荐全部为 Draw (平局)。命中 2/3 (66.7%)。但 CLV 三场全负，均值 -7.57%。这意味着市场收盘价持续高于我们的买入价——全球 Sharp Money 在临场前一直做空平局。

7.3.2 诊断: 信息颗粒度断层

V2 使用 last_5 (近5场得失球率) 计算 att_def_spread。这个宏观统计在 08:00 是有效的——但在 T-60min 临场首发公布后，Sharp Money 根据 主力伤停、首发轮换 进行天量资金对冲。V2 引擎看不到阵容变化，自然被掌握内幕的资金碾压。

7.3.3 杯赛/边缘联赛噪音

拜仁vs巴黎: 欧冠淘汰赛，战意因素复杂。Shabab Al Ahli: 阿联酋超，数据透明度极低，临场资金具有极强的操控性和内幕性。

7.3.4 统计学视角: 3场 = 噪音

3 场比赛远不足以做出统计推断 (需要 30-50 场)。目前不应修改 V2 代码——需要积累更多样本让正态分布说话。

7.4 CLV 计算公式

# True CLV (去水收盘线价值) 1. 计算 Pinnacle 收盘三向隐含概率总和 (Overround): margin = 1/H + 1/D + 1/A 2. 去水 → 公平概率: true_prob = (1/D_odds) / margin 3. 公平收盘赔率: fair_closing_odds = 1 / true_prob 4. CLV: true_clv = placed_odds / fair_closing_odds - 1
